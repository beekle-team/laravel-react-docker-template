# ユーザー認証機能 - 要件定義

## 概要

ユーザーの登録・ログイン・ログアウト機能を提供する基本認証システム。

### 設計概要

| 項目               | 内容              |
| ------------------ | ----------------- |
| **ユースケース数** | **3件**           |
| **シナリオ数**     | **5件**           |

### 本設計の特徴

1. **ユースケース駆動**: 認証の基本フローを3つのユースケースで定義
2. **振る舞い重視**: 各ユースケースをGiven-When-Then形式で記載
3. **テスト駆動**: 5つの具体的なテストシナリオで品質を保証

---

## 1. ユースケース一覧

### 1.1 全体マップ

```
[認証機能]
├─ UC-01: ユーザー登録
├─ UC-02: ログイン
└─ UC-03: ログアウト
```

### 1.2 優先度と概要

| ID    | ユースケース名   | 優先度 | シナリオ数 |
| ----- | --------------- | ------ | ---------- |

## 2. ユースケース詳細

### UC-01: ユーザー登録

#### 概要
未登録ユーザーが新規アカウントを作成する。

#### アクター
- 未登録ユーザー

#### ビジネス価値
新規ユーザーを獲得し、サービス利用を開始できるようにする。

#### 前提条件
- 登録フォームにアクセスできる
- 有効なメールアドレスを持っている

#### 基本フロー

**Scenario 1.1: 有効なデータで新規ユーザーを登録できる**

```gherkin
Given 有効なユーザーデータ（名前、メール、パスワード）
When 登録APIを呼び出す
Then ユーザーが作成される
And 認証済み状態になる
And ダッシュボードにリダイレクトされる
```

**Scenario 1.2: 重複メールアドレスでは登録できない**

```gherkin
Given 既存ユーザーと同じメールアドレス
When 登録APIを呼び出す
Then バリデーションエラーになる
And emailフィールドにエラーが表示される
```

#### 受け入れ基準
- [ ] 有効なデータで新規ユーザーを登録できる
- [ ] 重複メールアドレスでは登録できない
- [ ] 登録後は自動的にログイン状態になる
- [ ] パスワードはハッシュ化されて保存される

#### 影響範囲
- `App\Http\Controllers\Auth\RegisteredUserController`
- `App\Models\User`

---

### UC-02: ログイン

#### 概要
登録済みユーザーがシステムにログインする。

#### アクター
- 登録済みユーザー

#### ビジネス価値
ユーザーが自分のアカウントにアクセスしてサービスを利用できる。

#### 前提条件
- ユーザーが登録済みである
- ログインフォームにアクセスできる

#### 基本フロー

**Scenario 2.1: 正しい認証情報でログインできる**

```gherkin
Given 登録済みユーザーが存在する
And 正しいメールアドレスとパスワード
When ログインAPIを呼び出す
Then 認証済み状態になる
And セッションが開始される
```

**Scenario 2.2: 間違ったパスワードではログインできない**

```gherkin
Given 登録済みユーザーが存在する
And 間違ったパスワード
When ログインAPIを呼び出す
Then ゲスト状態のまま
And 認証エラーが返される
```

#### 受け入れ基準
- [ ] 正しい認証情報でログインできる
- [ ] 間違ったパスワードではログインできない
- [ ] 存在しないユーザーではログインできない
- [ ] ログイン失敗時に適切なエラーメッセージが表示される

#### 影響範囲
- `App\Http\Controllers\Auth\AuthenticatedSessionController`
- `App\Http\Requests\Auth\LoginRequest`

---

### UC-03: ログアウト

#### 概要
ログイン済みユーザーがシステムからログアウトする。

#### アクター
- ログイン済みユーザー

#### ビジネス価値
ユーザーが安全にセッションを終了できる。

#### 前提条件
- ユーザーがログイン済みである

#### 基本フロー

**Scenario 3.1: ログアウトできる**

```gherkin
Given ログイン済みユーザー
When ログアウトAPIを呼び出す
Then ゲスト状態になる
And セッションが破棄される
```

#### 受け入れ基準
- [ ] ログアウトするとゲスト状態になる
- [ ] セッションが適切に破棄される
- [ ] ログアウト後に認証が必要なページにアクセスするとリダイレクトされる

#### 影響範囲
- `App\Http\Controllers\Auth\AuthenticatedSessionController`
